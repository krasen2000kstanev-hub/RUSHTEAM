# Правила за AI агенти (Codex, Claude) в Team Hub

Прочети целия файл преди да пипаш код. Ако задачата противоречи на правило оттук – питай, не импровизирай.

## Какво е проектът
Вътрешна платформа на екипа. Статичен сайт (GitHub Pages) + AWS Lambda API + DynamoDB.

| Файл | Какво прави | Не прави тук |
|---|---|---|
| `index.html` | разметка и всички `<dialog>` форми | логика |
| `app.js` | всички екрани; един файл, един обект състояние `S` | директни `fetch` – ползвай `S.db` |
| `data.js` | вход с Google, `S.db` (get/set/update/delete), опресняване на 15 сек. | екрани |
| `styles.css` | целият дизайн, променливите са в `:root` | – |
| `backend/src/index.js` | API маршрути | правила за достъп |
| `backend/src/rules.js` | кой какво може да чете/пише + `auditChanges` | достъп до базата |
| `backend/src/store.js` | DynamoDB (винаги със страниране през `all()`) | бизнес логика |

Раздели (`#today`, `#tasks`, `#timer`, `#board`, `#web`, `#events`, `#design`, `#due`, `#calendar`, `#reports`, `#team`, `#hr`) се рендерират от функциите `vToday`, `vTasks`, … в `app.js`. Един раздел = една функция. Не прави втора версия на съществуващ екран.

## Няколко агента едновременно: никой не пипа чужди файлове
Тази папка (`D:\SoffiaSummit\RUSHTEAM`) е „главната“: тук работи само потребителят и тук се събира готовата работа. Всеки агент (Codex, Claude) работи в **собствено копие** на проекта, на собствен клон. Git после събира промените и, ако двама са пипали едно и също място, спира и показва конфликта, вместо тихо да изтрие чуждата работа.

1. **Преди първата редакция** изпълни `git status --short`. Ако има промени, които не са твои, **спри и питай**. Друг агент работи в момента.
2. **Направи си копие** (веднъж за задача):
   ```
   git worktree add ..\RUSHTEAM-<агент>-<задача> -b <агент>/<задача>
   ```
   Пример: `git worktree add ..\RUSHTEAM-codex-tasks -b codex/tasks`. Работи само там.
3. **Когато си готов:** commit в своя клон, после `git fetch origin` и `git rebase origin/main`. При конфликт **спри и питай**, не избирай сам чия версия остава.
4. **Качване в `main`** само след изрично „качвай“ от потребителя: `git push origin <агент>/<задача>:main`. Ако push-ът бъде отказан, значи някой е качил междувременно: повтори точка 3.
5. Не трий чужди клонове и копия. Своето копие махни с `git worktree remove ..\RUSHTEAM-<агент>-<задача>`.

## Задължителни правила
1. **Едно място за всяко нещо.** Преди да напишеш функция, търси дали вече я има (`grep`). Например `csvCell`, `safeUrl`, `tryW`, `writeDay`, `fill`.
2. **Не оставяй мъртъв код.** Ако заменяш екран, изтрий стария. Никакъв код след `return`.
3. **Права се проверяват на сървъра** (`rules.js`). Скриването на бутон във фронтенда не е защита.
4. **Не презаписвай чужди данни.** За съществуващ запис ползвай `update` (PATCH), не `set` (PUT) с локално копие. Списъци, които няколко души пишат едновременно (коментари), се променят върху прясно прочетения запис.
5. **Историята на действията не се пипа.** Всяка промяна минава през `notify()`/`audit()` в `backend/src/index.js` и се пише в `AuditTable` без срок. Не добавяй TTL и не трий записи там.
6. **Нищо от терминала не влиза във файл.** PowerShell профилът на този компютър печата „Attempting to perform the InitializeDefaultDrives…“. Не пренасочвай изход на команда (`>`) към файлове от проекта. Ако видиш този ред във файл – махни го (той чупи целия CSS).
7. **След промяна на `app.js`, `data.js` или `styles.css`** вдигни версията `?v=` в `index.html`, иначе колегите виждат стария файл.
8. **Тестове:** `cd backend && npm test` трябва да минава преди commit. Нова логика в `rules.js` = нов тест в `backend/test/`.
9. **Не пускай нищо в продукция без изрично „качвай“ от потребителя.** Backend deploy: push към `main` (GitHub Actions) или README, раздел „Ръчно качване на бекенда“. Параметрите на stack-а не се презаписват – ползвай `UsePreviousValue`.
10. **Текстовете в интерфейса са на български**, кратки и ясни.
11. **На потребителя обяснявай с прости думи и сравнение от реалния живот.** Той не е програмист. За всяка промяна: какво е → с какво прилича от ежедневието → какво значи за екипа. Командите давай готови за копиране, по една.
